## 1. 产品定位

**随行案是一套面向方案设计场景的 AI 工作流产品模型。**

它的核心不是替人完成最终商业方案，而是把方案设计中最容易消耗人的低价值流程工程化处理，让人把精力放回真实需求、真实数据和关键洞察。

一句话：

> **AI 承载方案草案，人完成商业跃迁。**

---

## 2. 解决的问题

| 用户类型 | 真实问题 | 随行案提供的价值 |
|---|---|---|
| **普通用户** | 不知道怎么从空白文档开始，方案结构不完整 | 快速生成一版结构完整、可继续修改的方案草案 |
| **VIP 用户** | 每次方案都从零开始，经验无法沉淀 | 私人方案模板库、私人方案仓库、API 套餐和回流记录 |
| **企业用户** | 方案过程不可追踪，多轮修改后需求和数据容易漂移 | 需求数据绑定、版本留痕、部门协同、权限内控和组织资产沉淀 |

---

## 3. 核心方法论：70 / 20 / 10

| 结构 | 含义 | 产品承载方式 |
|---|---|---|
| **70% 真实输入** | 客户需求、业务数据、预算、资源、约束、执行条件 | 用结构化字段和方案草案稳定记录 |
| **20% 关键洞察** | 商业判断、方案杠杆点、非模板化创意 | 由人完成，决定方案上限 |
| **10% 工程化承载** | 模板、格式、版本、留痕、协同、回流 | 由工作流系统尽量吸收 |

> **模板保下限，真实输入定方向，关键洞察定上限。**

## 4. 产品架构

```text
GitHub 母仓
  ├─ 方法论与产品叙事
  ├─ 工作流规则与模板结构
  ├─ 版本记录与回流机制
  └─ 展示仓 / 参赛文档 / 合作说明

云平台运行层
  ├─ 服务器与数据库
  ├─ 前端页面与后端接口
  ├─ 大模型 API 调用
  ├─ 安全、防火墙、备份
  └─ 企业部署与持续运维

用户资产层
  ├─ 个人历史方案
  ├─ VIP 私人模板库
  └─ 企业子仓 / 权限 / 内控 / 复盘资产
```

一句话：

> **GitHub 保核心，云平台做运行；母仓保方法，子仓沉淀客户资产。**
