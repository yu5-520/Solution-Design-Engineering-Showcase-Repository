# 02｜产品架构：核心资产、运行交付与用户资产分层

> 本文回答一个问题：随行案的技术与商业架构如何分层，为什么适合半开源与企业交付。

---

## 1. 三层架构

随行案不是把所有内容都放在一个平台里，而是拆成三层：

| 层级 | 主要承载 | 是否开放 | 核心作用 |
|---|---|---|---|
| **核心资产层** | GitHub 母仓、展示仓、方法论、工作流、模板结构、版本记录 | 展示仓开放，母仓阶段性受控 | 保存随行案的产品骨架和可迭代能力 |
| **运行交付层** | 服务器、数据库、网页、API、大模型调用、安全、运维 | 不开放 | 让产品真正运行、部署、交付和维护 |
| **用户资产层** | 个人历史方案、VIP 私人模板库、企业子仓、客户数据、复盘记录 | 用户 / 企业私有 | 沉淀用户自己的方案资产和组织知识 |

一句话：

> **核心资产可展示，运行系统可交付，用户数据必须私有。**

---

## 2. 核心资产层：GitHub 母仓与展示仓

GitHub 在随行案中不是单纯代码仓库，而是产品核心资产的承载方式。

### 2.1 母仓承载

母仓适合保存：

- 工作流主链路；
- 输入 / 输出规则；
- 模板结构；
- 回流复盘机制；
- 版本处理逻辑；
- 需求—数据—方案模块绑定规则；
- 可执行流程；
- 技术实现；
- 企业版可复用底层模块。

母仓回答的是：

> **随行案怎么运行。**

### 2.2 展示仓承载

展示仓适合保存：

- 产品叙事；
- 商业价值；
- 架构说明；
- 合作路线；
- 参赛材料；
- 半开源边界；
- 对外信任背书。

展示仓回答的是：

> **随行案为什么值得相信。**

---

## 3. 运行交付层：云平台与企业部署

运行交付层负责把核心资产层的能力变成真实产品。

可承载内容包括：

- ECS / 云服务器；
- 数据库；
- 前端页面；
- 后端接口；
- 大模型 API 调用；
- 用户登录与权限；
- 文件存储；
- 安全防护；
- 防火墙；
- 备份与运维；
- 企业私有化部署。

运行交付层回答的是：

> **随行案如何被用户访问、被企业部署、被持续维护。**

---

## 4. 用户资产层：个人库、VIP库、企业子仓

用户资产层保存使用过程中产生的私有资产。

### 4.1 个人资产

- 历史方案；
- 输入记录；
- 常用需求字段；
- 草案修改记录。

### 4.2 VIP 资产

- 私人方案模板库；
- 私人方案仓库；
- API / 模型偏好；
- 客户记录；
- 回流复盘记录；
- 个人方案风格。

### 4.3 企业资产

- 企业内部模板；
- 客户需求数据；
- 部门流程；
- 角色权限；
- 审批记录；
- 方案版本；
- 成功案例；
- 项目复盘。

用户资产层回答的是：

> **用户为什么越用越离不开，企业为什么愿意长期付费。**

---

## 5. 产品模块视角

| 模块 | 所属层级 | 主要价值 |
|---|---|---|
| 草案生成模块 | 运行交付层 | 将结构化输入转成可修改方案草案 |
| 模板管理模块 | 核心资产层 / 用户资产层 | 提供通用模板，并支持私人或企业模板沉淀 |
| 需求数据绑定模块 | 核心资产层 / 企业资产层 | 将方案模块与真实需求、数据依据建立对应关系 |
| 版本留痕模块 | 运行交付层 / 用户资产层 | 记录修改原因、修改人、时间和影响范围 |
| 回流复盘模块 | 用户资产层 | 将有效方案经验沉淀为下一次可复用资产 |
| 权限内控模块 | 企业资产层 / 运行交付层 | 支持企业角色、审批、数据隔离和安全管理 |

---

## 6. 半开源技术路线

随行案适合采用半开源路线：

| 内容 | 开放策略 |
|---|---|
| 展示仓 | 开放，用于产品叙事、合作沟通、赛事背书 |
| 基础说明文档 | 开放，用于建立理解和信任 |
| 通用模板示例 | 可部分开放，用于降低用户理解门槛 |
| 母仓核心工作流 | 阶段性受控，成熟后可选择部分开放 |
| 服务器、数据库、API密钥 | 不开放 |
| 用户数据、企业数据 | 私有，不开放 |
| 企业权限、内控、定制规则 | 商业交付，不开放或授权交付 |

最短表达：

> **展示开源，核心受控，数据私有，企业定制。**

---

## 7. 平台合作边界

随行案可以使用云平台做运行、部署和推广，但核心资产不应完全绑定在单一平台。

推荐边界：

- GitHub 保存核心架构、工作流、模板与版本记录；
- 云平台承载服务器、数据库、API、安全和企业部署；
- 用户资产进入私人库或企业子仓；
- 商业深度能力通过 VIP 订阅和企业定制交付。

一句话：

> **借平台的运行能力，不交出产品的核心资产。**

---

## 8. 架构总结

随行案的架构价值是：

> **把方案设计能力从个人经验和临时文档中抽离出来，拆成可展示、可运行、可沉淀、可商业化交付的产品系统。**

最短表达：

> **GitHub 建信任，云平台做交付，用户资产形成续费和企业价值。**
